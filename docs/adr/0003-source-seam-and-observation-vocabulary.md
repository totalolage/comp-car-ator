# Source seam: `harvest(ctx) → AsyncIterable<Observation>` over a closed Observation union

Every Source adapter satisfies one interface, `Source { id; scope?; harvest(ctx) }`, and emits Observations from one closed union: `ListingSeen | ListingGone | FxRate | CatalogEntry | VariantFacts | ListPrice | SliceDone`. The context gives the adapter everything it may touch: the Http module, the harvest mode (incremental or full), a read-only Checkpoint for the run's scope (`lastRunAt`, `isKnown(ref)`, `sliceDoneAt(slice)`), the run's clock, a logger and an abort signal. Observations carry no source id and no timestamp; the Ledger stamps both from the run. This is the one external seam with many adapters (Sauto, TipCars, Bazoš, AAA Auto, Autoesa, AutoScout24, mobile.de, the vehicle register, EEA, Wikidata, price lists, ČNB), so its depth decides how much each Wave 1 stream has to know: an adapter author learns one method and seven Observation shapes, and everything else (paging, parsing, query slicing, stop rules) stays inside the adapter.

## Contract

- Lazy: no request before the first `next()`. Duplicates are allowed; the Ledger is idempotent.
- `full` means census of the adapter's `scope`: it yields a ListingSeen for every listing in that scope or throws. Census inference only touches listings last seen under the same scope, so adapter instances with different scopes (e.g. `scope: "de"` and `"at"`, or a narrowed test instance) never retire each other's listings. A thrown harvest, or a full run with any rejected Observation, never closes a census, so a broken parser cannot mark the site gone. Misses count at most once per day, so re-running a full harvest the same day is harmless.
- A census can span runs. An adapter that splits its scope into slices (AutoScout24 queries by make/model/year/price under the 4,000-result cap) yields `SliceDone { slice }` after each finished slice, with its own stable slice key. The Ledger records it durably in order, so a later failure keeps it. The full runs of a scope since its last complete full run form the current census: `checkpoint.sliceDoneAt(slice)` returns when one of them finished the slice, and the next full run skips such slices. The complete full run that ends the census counts a listing as missed only when none of the census's runs saw it. A slice with a rejected Observation is not done (its SliceDone is rejected), so it is harvested again. After a complete full run every slice starts null; an adapter may also redo a slice it judges stale.
- `incremental` may stop early (newest first, stop at `isKnown`). The Ledger never infers absence from incremental runs, and incremental runs do not refresh prices of listings they skip; price changes of known listings come from full runs, so each listing Source needs a full-run cadence (weekly or better).
- All network access goes through `ctx.http`, passing `ctx.signal` so aborts interrupt in-flight requests; the clock only through `ctx.now`. That is what makes the adapter testable through `harvest` with the replay Http adapter and a fixed `now`.

## Considered options (design it twice)

- **A1, chosen: one async-iterable `harvest` per adapter, closed union, run-stamped envelope.** One seam, one code path in the Ledger and runner. Streaming lets the Ledger batch transactions and lets the runner abort.
- **A2: two-phase adapter `listPages(query) → raw` + `parse(raw) → Listing[]`** (the shape the scrape research suggested). Parsing becomes testable without Http, but pagination and stopping move into the runner, and every site paginates differently (offsets, per-make categories, query slicing under AutoScout24's 4,000-result cap). The runner would grow per-site branches: shallow adapters, leaky runner. Rejected; adapters can still keep `parse` as an internal function with its own tests.
- **A3: one interface per kind (`ListingSource`, `CatalogSource`, `FxSource`)** with typed returns. The type would say what a Source emits, but it triples the seam and the runner's code paths, and real Sources emit several kinds (Sauto: used and new listings; a manufacturer price list: ListPrice and CatalogEntry). Rejected.
- **A4: push style `harvest(ctx, emit)`.** Simple to write, but no backpressure or natural cancellation, and tests need a fake sink. Rejected.
- **A5: adapter-stamped envelope (`source`, `observedAt` on each Observation).** Every adapter would have to get both right, and the run already knows them. Rejected.

An envoy-peer review (another model family) agreed A1 beats A2–A5 and pushed for the census-scope, rejection and same-day rules above, which are now part of the contract.

### Resumable slices

- **S1, chosen: `SliceDone` in the Observation stream, census spanning the full runs since the last complete one.** Progress travels the same ordered stream as the listings, so a recorded SliceDone implies its listings are recorded, with no second write path. Static `scope` stays the census boundary; slices are progress inside it, so adaptive re-slicing (splitting a slice that grew past the cap) and listings moving between price slices cannot strand or falsely miss listings.
- **S2: per-slice census (listings tagged with their slice, census on each SliceDone).** Resumes too, but a listing whose price moves it to another slice is missed by the old one, and splitting slice A into A1/A2 strands A's absent listings forever. Rejected after envoy-peer review.
- **S3: a write method on the context (`ctx.checkpoint.markDone`).** A second channel into the Ledger, ordered separately from the stream it describes. Rejected.
- **S4: one adapter instance per static slice.** Cannot follow adaptive slicing, which the result cap forces. Rejected for AutoScout24; still fine for coarse splits such as DE/AT.

## Observation vocabulary notes

- `VehicleDescriptor` is the raw description a Source gives (make/model/trim text, source taxonomy ids, registration, specs it states); it is the Resolver's input, together with the SourceId that namespaces the taxonomy ids. Sources map their own labels onto the closed value sets and leave a field undefined rather than guess.
- `CatalogEntry` fully identifies a Variant and is the only kind that creates one. `VariantFacts` carries partial Spec evidence from Sources that cannot identify a Variant on their own (EEA has no body, Wikidata is sparse): the Ledger resolves it at snapshot time and fills Specs the CatalogEntries left empty, never overriding them. Catalog Sources therefore never guess missing identity fields.
- `ListPrice` is a new price of one Offer in one edition. Offer identity is not Variant identity: several Offers (Trims, FWD/AWD, packs, model years) resolve to one Variant, and none of the descriptor fields reliably tells them apart, so the Source gives each Offer a stable `ref` (sales code or curated row key, unique within the Source). The Ledger keys editions by (source, ref, `validFrom`); a later edition replaces earlier ones of its Offer, never another Offer's. `validTo` (inclusive) ends an edition: from the day after, the Offer has no New price, and an older edition never comes back. To withdraw an Offer the Source re-emits its current edition with `validTo`; an Offer simply missing from a list stays current. Dealer new and demo cars are `ListingSeen` with `condition` new/demo, not ListPrice.
- `ListingSeen.sellerExtras` carries charges the seller invoices on top of the price (delivery, preparation, dealer fees), in the price's currency and with their own price basis, since a net car price can come with gross fees. Pricing normalizes them like the price and puts them in the CZ VAT base of a new car; the asking price stays unchanged.
- `ListingSeen.inspectionValidUntil` carries a shown German/Austrian inspection date into the landed price.
- `FxRate` is per single unit (`kurz / množství`), so per-100 quotes are normalized at the Source.
- Adding an Observation kind is a breaking change to the seam: extend the union, the Ledger's validation and recording, and this ADR together.
