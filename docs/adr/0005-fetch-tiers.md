# Fetch tiers are internal to Http; callers see only `get(request) → Page`

Sources reach websites through one Http module whose interface is `get(request) → Page`. Inside, three fetch tiers sit behind an internal seam (`TierFetcher`): T0 is plain `fetch` with browser headers; T1 is TLS/HTTP2 impersonation (Impit, Chrome profile); T2 is a stealth browser (Patchright driving the system Chrome, or Camoufox), off unless enabled. Http starts at T0 (or the request's `minTier`), recognizes bot challenges (Cloudflare, Akamai, EdgeOne, DataDome, PerimeterX, Imperva markers), and escalates to the next available tier; a challenge at the highest tier rejects with `HttpBlockedError`. Pacing (~1 request/s per host by default, serialized per host, hosts in parallel), retry with backoff on 429/5xx and network errors, and charset decoding live here too. We hid the tiers because the research showed protection differs by site and changes over time (TipCars passes T0 with a Chrome UA today but may need T1 from datacenter IPs); if each adapter chose its own tool, every protection change would touch adapters instead of one module.

## Consequences

- Escalation also happens on a plain 403 without a known marker, since an unrecognized bot rule looks like that; a 403 from the last tier is returned as a Page. 429 and 5xx are retried at the same tier, never escalated: rate limits follow the IP, not the client.
- A request holds its host's turn through its retries and tiers, so the requests queued behind it wait out its backoff too; a 429 that used up its attempts leaves its Retry-After as a cooldown on the host. A challenged response escalates whatever its status (a 429 with `cf-mitigated: challenge` is a challenge, not a rate limit). `HttpRequest.hostIntervalMs` lets a Source slow down for its site (it raises the configured interval, never lowers it); runner-level overrides go in `hostIntervals`.
- After `maxConsecutiveBlocks` (default 3) requests to one host end blocked in a row, the Http stops sending that host anything for its lifetime: later and already-queued requests reject with `HttpBlockedError` at once. This is the circuit breaker the scraping line asks for ("stop on repeated challenges"); a run that hits it fails that source and leaves the others alone.
- T1 headers come from Impit's Chrome profile (User-Agent, client hints, Accept) so they match its TLS fingerprint; only the caller's headers and Accept-Language go on top. Impit loads on first use.
- T2 is opt-in: `createLiveHttp({ browser: { engine } })` or `CCA_HTTP_BROWSER=patchright|camoufox`. It needs a browser outside `pnpm install` (system Chrome for Patchright; `camoufox-js` plus its ~1.3 GB browser for the experimental Camoufox engine, not a dependency) and, headed, a display (`xvfb-run`). It renders the page (Accept-Language becomes the browser's locale; the caller's other headers go over the browser's own on main-frame navigations and their redirects, so subresources keep the browser's fingerprint; a caller's Cookie header is dropped there, the browser sending its own cookies), polls a page that still shows a challenge for up to 20 s, and closes the browser after 30 s idle or on `LiveHttp.close()`. CI never needs it: its test runs only with `CCA_HTTP_T2_TEST=1`. T2 exists for sites that pass a canary only in a real browser.
- The `patchright` engine starts the system Chrome (`google-chrome` on PATH) as a plain process with only a profile directory, `--lang` and a DevTools port, and attaches Patchright over CDP once it runs; `close()` disconnects and stops the process (SIGKILL after 5 s). From the home IP, mobile.de's Akamai denied every browser an automation library launched (Patchright with its default switches, with none at all, without locale emulation; Camoufox) and let through Chrome started this way, cold profile or warm (ADR 0014). The locale is Chrome's own language rather than context emulation (on Linux Chrome reads it from `LANGUAGE`/`LANG`, which T2 sets per profile; `--lang` alone leaves it English), so Accept-Language (`de-DE,de;q=0.9,en-US;q=0.8,en;q=0.7`) and `navigator.languages` come from the browser and agree. Akamai's interstitial (`sec-if-cpt-container`, a 200 that reloads itself into the page once its sensor is accepted) counts as a challenge, so T2 waits for it to clear and T0/T1 escalate.
- The raw response cache (`createLiveHttp({ cache: { dir, maxAgeMs } })`) stores final Pages except 429/5xx on disk, one JSON file per request, keyed by URL (query order ignored), `binary`, locale, headers and `minTier`; `stream` requests skip it. A hit skips pacing and network. Entries use the cassette's `Interaction` shape, so they can be copied into fixtures. It never expires by default: the ingest runner gives each run its own directory or sets `maxAgeMs`, otherwise an incremental run would see stale first pages.
- The replay adapter applies the same challenge rule to recorded responses, so an adapter's handling of blocks is testable from fixtures.
- Any final HTTP status is a Page; deciding that 404 means "listing gone" is the adapter's job.
- Http is GET-only. `binary: true` returns raw bytes (`Page.bytes`) for PDF price lists and ZIP datasets; cassettes store them base64-encoded.
- `stream: true` is for downloads too large for memory (the vehicle register is one multi-GB CSV with no length and no range support). The Page then carries `chunks: AsyncIterable<Uint8Array>`. Only a 2xx response that is not HTML streams; anything else is read in full first, so challenge detection, retries and escalation work exactly as for other requests, all before the first byte; such a Page has its text in `body` and serves it again through `chunks`. T0 streams from the network; T1 and T2 read the body in full and serve it as chunks. Impit (T1) cannot stop a native request before its headers arrive (an abort only ends the wait) and its own timeout covers the whole body, so a T1 stream request is read in full under Impit's timeout, which ends the native request and its socket with it, and fails once the body exceeds 256 MiB (considered: a local SOCKS tunnel per request that our code closes on abort, which keeps T1 streaming at the cost of a proxy in the adapter; no streamed Source needs T1 today). At T0 `timeoutMs` limits the wait for the headers and then each chunk read, not the whole download; a read that times out stops the iteration with a `TimeoutError` and closes the connection, and time the consumer spends between reads does not count. A streamed response holds its host's turn only until its headers arrive, so a slow consumer does not delay other requests. Aborting the request's signal stops the iteration with the abort reason, and stopping the iteration early cancels the download. Stream requests bypass the raw response cache in both directions. The replay adapter serves a recorded body as 64 KiB chunks, so parsers meet chunk boundaries in tests; `recordingHttp` writes a streamed body into its Interaction as the consumer reads it, so a fixture is complete only once read to the end. Measured: 300 MB streamed through T0 from a local server at 117 MB peak RSS.
  - Considered: a separate `download(request)` method (a second entry point duplicating pacing, retries and challenge handling, or sharing them through an extra internal seam) and returning a web `ReadableStream` (ties Sources to the WHATWG stream API, while `for await` over an AsyncIterable is all a parser needs and replay can produce one from a buffer). The request flag keeps one `get` and one policy path.
- Caller headers follow redirects at every tier. T0 drops Authorization and Cookie when a redirect leaves the origin; T1 (Impit) keeps both, and T2 navigations keep Authorization (Patchright re-applies a route's header overrides to redirects), so a Source should not send credentials to a site that redirects elsewhere.
- `request.signal` aborts in-flight fetches, pacing waits and backoff waits (a T2 page closes its tab; a T2 binary fetch runs in a request context of its own, seeded with the browser's User-Agent and cookies and handing back the cookies it changed except those the browser holds changed at hand-back, which an abort or `close()` disposes to close the connection); T0/T1 attempts time out after 30 s (`timeoutMs`; for a `stream` request at T0, the wait for headers and for each chunk) and count as network failures.
