# The catalog comes from the Czech register; EEA and Wikidata only add to it

The catalog's Variants are counted out of the Czech vehicle register's open data (`rsv` Source): its monthly export lists every vehicle ever registered in CZ with its type-approval data, so vehicles that share make, model, type-approval type, body, fuel and power are one Variant once at least `minVehicles` (default 5) of them, made from 2000 on, back it. The EEA CO2 dataset (`eea-co2`) has no body, so it yields VariantFacts (engine size, WLTP CO2, mass, consumption) that the Ledger resolves onto those Variants. Wikidata is not a Source: it cannot state a Variant or a Spec the Ledger lacks, but it names generations, tells which types form one and where a type runs into the next generation, so the `rsv` adapter joins it in, and a run fails without it (types would regroup and re-key Variants).

## How the register maps onto the vocabulary

- **Generation = type-approval type, unless Wikidata's dates say otherwise.** The register has no generation, but the EU type-approval type ("5E" Octavia III, "NX" Octavia IV, "204" C-Class W204) changes with each design cycle for most makes. Variant codes glued onto a type ("BWYD6BA") fold into the shortest type of the model they start with ("BWY"), whatever the counts. A type starts as a dated Wikidata generation of the same model when that generation starts within two years before or one after the type's first core registration year (10th percentile) and no other generation with an end date spans the type's core years; types that start as one generation are one, keyed by Wikidata's word for it (`skoda/octavia/mk2`, `volkswagen/passat/b6`) and named with the words listings use ("Golf VII (Mk7, 5G, AU)"), which the Resolver reads. VW kept some types for the next generation (Golf 1K: V and VI; Passat 3C: B6 and B7): when a type outlasts its generation and the dated generation starting within a year of that end is not another type's start, the type's vehicles are split by manufacture year. A year that another dated generation's dates hold too (Golf 2008–2009, or a successor another type starts as) or past the last one (bar one run-out year) is left out, not guessed; a generation without an end date contests only the years of generations that started before it, since a later start is the firmer fact. A candidate split across generations states no Specs, since its counters cannot be split by year. A type Wikidata does not date is its own generation, keyed and named by its code ("Octavia 5E"), so a listing that writes "Octavia III" resolves to the Model, not a Variant (the Resolver blocks generation claims the catalog lacks): coverage is lost, precision is not. A type whose code is a dated generation's word, or two dated generations with one word, would collide on a key and are left out.
- **Make = the make the "Tovární značka" field names, not the company or model it may hold.** Company words go ("ŠKODA AUTO A.S.", "TESLA MOTORS", "AUTOMOBILI LAMBORGHINI S.P.A."), a known make the field starts with is the make ("ŠKODA OCTAVIA", "VW GOLF", "FORD-CNG-TECHNIK", "MINI COOPER"), unless the rest names another make or sub-brand ("BMW ALPINA", "HONDA ACURA" stay), and a short table maps companies and badges of one make ("QUATTRO" → Audi, "MCC", "MICRO COMPACT CAR" → Smart, "GM DAEWOO", "MARUTI"). For companies of several makes the commercial name's first word decides ("JAGUAR LAND ROVER LIMITED" + "RANGE ROVER SPORT" → Land Rover, "DAIMLER CHRYSLER" + "A 170" → Mercedes-Benz), else the company's name stays. EEA's makes go through the same function.
- **Model = the commercial name's model part.** "OCTAVIA COMBI 1.9 TDI" → Octavia, "C 220 CDI" → C-Class, "320D" → 3 Series (spellings the Resolver's alias groups know). A name listing one car under its market names is the first of them ("TUCSON, IX35" → Tucson, "KONA, KAUAI" → Kona, "TRANSIT/TOURNEO" → Transit); Audi's and Suzuki's lists name different models ("A3, S3", "SX4, S-CROSS"), so the vehicle could be either and the list stays the name. Power, drive and engine badges after the model word go ("Q4 40 E-TRON" → Q4 e-tron, "I4 EDRIVE35" → i4, "X3 20D" → X3, "RX450H" → RX, "AMG C 43" → C-Class), as do Mini's trim words around Countryman and Clubman. Names split by a space are joined where the make writes them as one ("X 5", "C 5", "XC 60", "RAV 4", "500 L"; Mazda "CX 9" → CX-9), BMW's bare series numbers and "Řada 3" are the 3 Series, and a few register misspellings are fixed ("PASAT", "KODIAK", "RAGNE ROVER"). A name with no letter or digit (".") is no model; its rows are counted as "no-model". Spellings of one model id on one type ("UP!", "UP") are one model, named by the spelling with most vehicles, so their Variants cannot share ids. A name that extends a shorter one only by badges (a word with a digit, "XC90 D4", "Range Rover Velar P380", "Golf 1J"; or a listed trim, fuel or body word, "Golf R", "Evoque HSE Dynamic", "911 Carrera GTS", "Astra Caravan") is that model on the shorter name's types; on a type of its own it stays ("Ioniq 5"). Names that differ otherwise stay apart, even on one type: models share types (a Tiguan Allspace approved as a Tiguan, Golf Plus on the Golf's, a few "RANGE ROVER" rows with a Range Rover Sport's type), and neither the type nor the counts tell a badge from a model, so only the name's words decide, never which name has more vehicles.
- **Body** from the EU body code (AA sedan, AB hatchback, AC wagon, AD coupe, AE convertible, AF MPV); off-road category M1G is SUV. Older national approvals that state only doors ("5 DVEŘOVÁ") are skipped.
- **Fuel**: BA → petrol, NM → diesel, LPG, CNG; the electric flag → bev; the hybrid flag with class OVC-HEV → phev, NOVC-HEV → hev.
- **Production years** are the 2nd–98th percentile of the backing vehicles' manufacture years (else first registration, CZ or abroad); a Variant is ongoing (no `to`) while at least 2% of its vehicles are from the export's year.
- **Specs** are the value at least half the vehicles stating it share (Misra–Gries counters, so memory stays per Variant, not per vehicle); a split Spec (Kodiaq with 5 and 7 seats) is left out.
- Rows that cannot be mapped (no power, unknown fuel or body, no type) are counted and skipped; only a changed column set fails the run.

## Considered options

- **Wikidata as the generation source**: rejected. In 2026-10 only 181 Wikidata car generation items have dates, Octavia III/IV and every BMW generation among the missing ones; dropping the types it does not date would drop most of the catalog.
- **Wikidata item ids as generation keys**: rejected. They would survive a relabel, but ids like `q1234` match no other Source's keys, while `mk7`/`b6` do; the Ledger's catalog census absorbs the rare relabel.
- **Splitting Spec counters by year**: rejected; it multiplies per-candidate memory by the year span to serve the few types kept across generations.
- **A curated generation table** (make/model/type → numeral): deferred. It would let "Octavia III" listings match, but every entry needs checking against the register's years; start with the top CZ models when the Resolver's coverage numbers show the loss.
- **Dropping rare neighbours** (a Variant 20× smaller than one differing only in power ±3 kW, body or fuel): rejected after envoy-peer review. A missing Variant can make a listing match the wrong one; an extra one only makes it ambiguous.
- **Per-model tables for the register's lists** ("A3, S3" by power into A3 or S3, "SX4, S-CROSS" by type): deferred. Each entry needs checking against the export, and the lists hold few Variants.
- **Folding names by type**: rejected. Folding a longer name into any shorter one that has its type (the rule until 2026-10) let a handful of "RANGE ROVER" rows carrying a Sport, Evoque or Velar type pull every vehicle of those models into the Range Rover (release 2026-10-26: Range Rover held types LS, LV, LW, LY and LZ, and the catalog had no Range Rover Sport), and the catalog likewise lacked Golf Plus, Golf Sportsvan and C4 Picasso. Giving each type's vehicles to whichever related name holds most of them (tried after) hands a Tiguan Allspace sharing a Tiguan's type to the Tiguan or the reverse, flipping with the counts between exports. A badge the word list does not know ("Altea Freetrack", "C3 Flash") or a misspelt model word ("C4 Picaso") so stays a model of its own until a list learns it: an extra Model only makes listings ambiguous, a wrongly merged one makes them match the wrong car.
- **EEA as a second CatalogEntry source**: rejected; without body it cannot identify a Variant (ADR 0003: VariantFacts).

## Consequences

- The export is about 19.5 million rows (≈10 GB of CSV). The stable URL serves it uncompressed; the monthly ZIP (≈2 GB) is found the way the site's page finds it (`GET /` hands out an `_ren` API token, the reports API lists the export's GUID and generation date). Neither supports Range, and the server resets long downloads (observed after 10 and 87 minutes), so the adapter streams the ZIP (`HttpRequest.stream`, ADR 0005; inflated on the fly), holds one record per candidate Variant, and starts the download over up to `attempts` (3) times; Variants are yielded only after a complete read. The generation date also lets an incremental run skip an export it has seen without downloading it.
- Generation keys come from Wikidata's words or a type's code, not from counts, so a monthly export keys the same Variants as the last. They still move when Wikidata dates a generation it did not (5E becomes mk3), relabels one, or a shorter type code first appears. The Ledger therefore treats a `full` run of a Source as a census of its CatalogEntries too: entries in the run's scope that no run of the census stated are retired from the catalog (re-stating one restores it), so a re-keyed Variant leaves no duplicate behind. Only full runs retire, so the ingest schedule runs `rsv` in `full` mode (it reads the whole export either way).
- Changing how names are cleaned or folded re-keys the Variants concerned (`land-rover/range-rover-sport/...` instead of `land-rover/range-rover/...`). Old ids leave only through the census rules (ADR 0003), so not always at the next `full` run: a full run with a rejected Observation applies no census and keeps old and new ids both, and a full run that yielded old ids before it failed joins the census the next complete run closes, which therefore keeps them one census longer (`rsv` yields only after reading the whole export, so this needs a failure after yielding began). Until the first clean census that no run stated them in, the snapshot, and a Bundle published from it (`ingest run --out`, `publish`), lists a model under both its old and new name. That overlap is accepted: an extra Variant only makes a listing ambiguous, and the first clean census in which no run restates the old ids clears it; listings resolved to an old id re-resolve at the next snapshot.
- Splitting by dates leaves out the vehicles of overlap years and of types whose next generation Wikidata does not date; on the 2026-10 fixture 16 of 501 cars.
- EEA data is CC BY 4.0 and needs visible attribution (`EEA_CO2_ATTRIBUTION`); the register's NKOD record states no terms of use (`RSV_ATTRIBUTION`). Showing them on the site is the web's job.
