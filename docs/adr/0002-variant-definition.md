# Variant = make + model + generation + body + fuel + power

A catalog Variant is identified by make, model, generation, body, fuel and power (kW), and its id is the path slug `make/model/generation/body-fuel-<kW>kw` (e.g. `skoda/octavia/5e/wagon-diesel-110kw`). Trim, transmission, drive, colour and model year are not part of the identity. This is the level at which used listings can be told apart reliably and that the free catalog Sources can state: Czech and German listings state fuel and power far more often than trim, and the vehicle register and EEA datasets carry power and fuel but no trim and no gearbox. The gearboxes a Variant is offered with are a Spec (`transmissions`), stated by Sources that know them (manufacturer price lists); listings keep their own `transmission`. Trim lives on new prices (a Variant has a new-price range across trims) and as raw text on listings.

## Considered options

- **Include transmission** (the Wave 0 definition): dropped in Wave 1. No $0 catalog Source states the gearbox: the Czech register's open data (99 columns) has driven axles, body, fuel, kW and seats but no gearbox; the EEA CO2 data has none; Wikidata has none per variant. With transmission in the identity the register could only emit VariantFacts, and nothing but a few manufacturer price lists would create Variants.
- **Transmission in the id only when the Source knows it** (`…-110kw` from the register, `…-110kw-automatic` from a price list): rejected. Both ids would name the same car, so listings would match either and the catalog would hold duplicates.
- **Decode the gearbox from type-approval version codes** (VW Group "Verze" codes such as `FM5`): rejected. Unverified, and it would cover one manufacturer group; every other make would still lack it.
- **Include trim** (Octavia Style vs Ambition): rejected. Listings name trims inconsistently or not at all, so most listings would only resolve to the Model, and trims are renamed between model years.
- **Include drive** (FWD vs 4x4): rejected for now. Within one power output, 4x4 variants are rare, and listings often omit drive; the Resolver would turn many matches into ambiguities. Drive is a Spec; revisit if 4x4-heavy models (Kodiaq, Superb) show collisions.
- **Engine code or type-approval number**: rejected. Precise, but listings never show them, so Resolution could not use them.

## Consequences

- Ids are stable as long as a catalog Source keeps the same generation slug; renaming a generation slug re-keys its Variants.
- Two catalog Sources describing the same Variant converge on one id and are merged field by field in the Ledger; their `transmissions` are united.
- Power within ±3 kW counts as the same Variant during Resolution, to absorb kW/PS rounding.
- Resolution prefers a Model to a wrong Variant, because matched listings feed per-Variant price stats and `VariantFacts` fill catalog Specs. A listing resolves to a Variant only when it states fuel and power (in fields or trim text) and exactly one Variant fits every field it states; fitting Variants are never ranked against each other (closer power, likelier year). Registration year may be a year either side of the production years, so generation boundary years stay ambiguous unless the text names the generation. Text that names a generation the catalog lacks ("Kodiaq I", "W212" when only the W213 is catalogued) blocks a match (a lone upper-case "I" or "V" names a generation only right after the model name, however the listing spells the model, or as the first trim word; a lone lower-case "i" or "v" never does, since Czech "v záruce" is "under warranty"), and so does hybrid or electric wording that contradicts the listing's fuel ("1.4 TSI Plug-in Hybrid" is not a petrol Variant). The rule and the make/model alias data live in `packages/resolver`; its evaluation set (real Sauto and AutoScout24 listings, hand-labelled) guards precision and coverage.
- Body is identity, but the register and listing sites name it differently: the register files a car by its EU type-approval body code (an SUV outside the off-road category is a wagon, MPV or hatchback; a liftback such as the Octavia is a sedan; one MPV is filed as MPV or wagon; every Golf VIII, hatchback or estate, as a wagon), sites and price lists by shape. When no Variant fits a listing's stated body, the Resolver tries the register bodies that can be that car: SUV → wagon, MPV or hatchback; hatchback ↔ sedan; MPV ↔ wagon. The stated body wins whenever a Variant fits it; coupés, convertibles, vans and pickups have no stand-in. Considered and rejected: dropping a body the catalog lacks (a Golf Cabrio would match a Golf); hatchback → wagon, even only in generations without hatchback or sedan Variants (Golf VIII), because a generation can lack its hatchbacks for other reasons (the Golf VI's 5K type is not catalogued, so its hatchbacks would land on real Golf VI Variant estates); rewriting register bodies into shapes in the `rsv` adapter (the register has no shape column; a per-model table would re-key Variants).
- Transmission is a filter, not identity: a listing that states a gearbox does not match a Variant whose `transmissions` exclude it, and does match a Variant without `transmissions`. Manual and automatic cars of one Variant share its price stats; the Publisher can split them by the listings' `transmission` if the difference matters.
